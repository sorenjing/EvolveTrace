解压包检查覆盖：

1. 在独立端口、临时数据库和隔离偏好下，由 SessionStart 启动准备好的运行环境并收件。
2. 工作台返回 HTTP 200。
3. 再次调用 SessionStart 复用同一个服务进程。
4. 合成工具输入和输出以相同调用标识入库。
5. 暂停持久化，已有工作台保留。
6. 暂停时普通合成事件不再上报。
7. 暂停时本地危险模式拒绝输出仍存在；只传入载荷，不执行危险命令。
8. 恢复复用原服务，后续事件重新上报。
9. 归档版本与源码一致，控制 Skill 的相对路径在带空格的解压目录中可解析。

上述条目合计对应 11 个断言。既有测试还覆盖并发启动、缺少运行环境/静态页面、配置损坏、探针总时限、启动超时清理，以及暂停与启动锁竞争。

## 客户端升级后的人工验收

1. 核对安装副本的 `.codex-plugin/plugin.json` 为 `0.3.1`，并且可发现 `$control-evolvetrace`。Git 来源需包含已推送的对应源码。
2. 用户通过宿主支持的界面审核并信任当前 Hook；安装、启用和旧版本信任均不能代替此步骤。不要编辑 trust hash 或使用跳过信任的启动参数。
3. 新开项目会话，执行 `git status --short` 等无害只读任务。核对新的 SessionStart、工具前后事件及调用关联；已有对话继续上报不能证明新会话启动已验证。
4. 使用控制 Skill 查看状态，记录服务进程身份；再次新开会话，确认复用。
5. 暂停后执行一次无害任务，确认后续采集暂停、工作台仍可访问、Context 仍可交付；恢复后再次检查新事件。使用隔离会话和足够清晰的时间边界，保留在途事件可能完成的限制。
6. 若需要完整 Task 验收，按[使用手册](usage.md)准备并绑定 Task；没有 Task 的普通会话不是绑定失败，也不能据此判定任务合格。

推荐命令（仓库根目录）：

```powershell
python ./plugin/hooks/runtime_control.py status
./scripts/observe.ps1 -ExpectEvidence
```

`status` 的 `service=ready` 只说明服务可达；`observe.ps1` 成功只证明其实际检查项，不能证明当前 Session 完整、Hook 均已获信任或产品收益。遇到缺失应检查插件版本、信任、触发、传输及绑定层，保留 unknown。

Hook 信任规则参见[官方插件文档](https://developers.openai.com/plugins/build/plugins)。效果与独立试用记录继续使用[效果验证指南](effectiveness.md)。
