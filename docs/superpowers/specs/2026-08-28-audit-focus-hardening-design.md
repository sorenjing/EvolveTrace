# EvolveTrace 审计主线加固设计

## 目标

把仓库从“旧版 Agent 执行器与新版审计工作台并存”收敛为一个本地优先的 Coding Agent 审计工具。保留 Codex Hook 采集、脱敏、风险规则、SQLite 审计、SSE 推送和 Next.js 审查界面，不再提供执行 Agent、调用 LLM、动态工具或管理角色的能力。

## 边界

- 保持 `/api/audit/*` 接口和插件 Hook 配置兼容。
- 保留当前审计页面，不增加新的前端功能。
- 删除仅服务旧 Agent 执行器的后端模块、路由、依赖、测试和未使用前端组件。
- 更新 README、设计文档和项目开发说明，使定位与代码一致。
- 不修改审计事件协议，不虚构性能或用户指标。

## 实现

后端入口只装配审计路由、CORS 和健康检查。审计路由继续要求 loopback 请求；采集脚本继续在事件离开 Codex 进程前执行第一轮脱敏，后端模型执行第二轮脱敏并持久化处理后的结构。

新增一组脱敏后的真实形态 Hook fixture，并通过回放测试验证：同一工具事件只持久化一次、原始凭证不进入数据库、风险结果可从会话查询恢复。演示脚本复用同一事件协议，避免维护第二套伪造结构。

前端只保留当前审计页面引用的组件与类型。CI 继续执行后端测试、前端 lint 和 production build。

## 验收

- 仓库不再暴露 `/api/agent/*`、`/api/admin/*`、`/api/tools` 和 LLM 配置测试接口。
- Hook 采集、脱敏、事件去重、SQLite 恢复、风险规则和 SSE 测试通过。
- 前端 lint 与 production build 通过。
- README、DESIGN.md、AGENTS.md 与实际架构一致。
