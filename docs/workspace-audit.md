# 跨项目执行审计与确认记忆

Context 提供工作区项目目录，EvolveTrace 把采集记录按项目归类，显示命令分类、
重复操作及失败重试线索。人工确认后，结论可以在后续任务中按项目回读。

## 连接项目目录

启动本地 EvolveTrace 服务后，在已配置 `.aictx.toml` 的工作区执行：

```powershell
aictx audit sync --dry-run
aictx audit sync
aictx audit report
aictx audit report demo
```

可用 `--workspace <工作区>` 显式指定工作区；服务地址默认为
`http://127.0.0.1:8001`，可用 `--evolvetrace-url` 选择其他 loopback 地址。
预览离线显示目录。同步通过 `workspace-index/v1` 提交项目名称和路径，不读取
其他项目的语义记忆。后端不导入 Context 内部模块，也不解析 Markdown。

同名项目通过工作区身份区分。每条事件按工作目录归入最深的已登记项目；未知
目录保留为未归属。登记也适用于已有证据。重新同步将移出的项目标为历史项目，
保留证据和已确认记忆。工作区绝对根目录仅用于本机路由，不出现在报告中。

## 统计范围与规则

总览覆盖已采集事件中的全部命令，包括未归属目录。项目统计仍只使用可按工作目录
确认归属的事件；Hook 仅上报工作区根目录时不推测具体项目。

归属优先使用可按会话和调用 ID 核对的 `CommandExecution` 完成记录，其次是工具输入的
绝对 `workdir`/`cwd`，最后才是 Hook 的目录。会话根目录不自动代表整场会话属于某个项目。
界面分别显示这三类归属依据的事件数。

完成记录仅从该事件 `transcript_path` 指向、且位于当前 `CODEX_HOME/sessions` 的本机
JSONL 中提取；默认 `CODEX_HOME` 为用户目录下的 `.codex`。每次查询最多检查最近
4 个引用文件，各读最多 64 KiB 头部以核对会话，再读末尾 1 MiB；不扫描会话目录。
仅使用匹配的会话 ID、调用 ID、记录类型和执行目录，不返回或存储日志中的对话与输出。
不支持的格式、远端 URI、不匹配的记录和读取上限外的历史数据均保持原有未知状态。

已核对的执行目录保存为带规则版本及观察时间的独立回执，避免日志增长或服务重启
让项目统计消失；原始 Hook 事件不被改写。删除事件所属会话时同时删除回执。
统计与审计记忆的证据校验使用同一套归属规则，不能把其他项目的事件作为本项目记忆。

采集状态独立显示本次启动后的收件数、新增存储数、最后服务器收件时间、已观察
阶段及历史存储数，每 15 秒更新。最近 60 秒有收件标为 receiving，否则标为 quiet；
本次启动无收件为 awaiting_events。quiet 可能只是空闲，阶段出现过不等于覆盖完整。
重放旧时间戳以服务器接收时间计算，重复投递增加收件数但不增加存储数。

工作台可选择项目并实时更新。工具调用分为搜索读取、修改、构建测试、依赖管理、
Git、网络、组合命令和其他工具。组合 shell 脚本作为一次观察，不展开成已执行
的子命令。Pre/Post 有 `tool_use_id` 时合并；缺少标识时显示未配对数量，次数
可能偏高。有标识但缺少开始事件的结束观察也单独标出；分析窗口截断、服务晚启动
或采集缺失都可能导致配对缺口。阻断单独计数。耗时只累计显式 `duration_ms`，缺失结果保持未知。

时间线与后台均按同一会话的 `tool_use_id` 关联，`turn_id` 缺失不拆分一次调用；不同会话不会合并。前端也接受已收到的 `PostToolUseFailure` 作为完成观察，支持先收到完成再收到开始，且按事件 ID 去重。这不扩大插件在特定宿主上的实际事件覆盖。

同一调用若有多个不同事件 ID 的完成观察，时间线分别保留输出和风险，便于检查冲突；较晚成功不会隐藏先前失败。时间线的证据步骤数不等于实际调用次数，后台仍按调用关联并保留结果冲突为未知。
不同事件 ID 的重复开始观察也单独保留，避免覆盖其中的安全拒绝证据。

`activity/v1` 在每个会话最近 600 秒的已采集操作窗口内检查：

- 同一命令、同一目录至少五次搜索读取或构建测试，期间未捕获修改证据；
- 同一命令、同一目录至少三次连续观察失败，成功或未知结果打断失败序列。

提醒带事件引用，始终需要核对。正常验证也可能命中；没有捕获到修改不能证明
实际文件没有变化。缺失时间戳、无法区分的脱敏命令和等待执行的调用不触发重复
提醒。“忽略本次”针对会话及命令，“静音此类”针对项目及规则，设置可以恢复。

报告分析全库最近入库的最多 20,000 条事件，项目过滤不会扩大范围。
`event_limit`、`observed_event_count`、`truncated` 明确描述覆盖。
分析按需查询，每个不同工作目录匹配一次，不增加同步 Hook 的分析工作。

服务启动时运行独立的后台证据补齐任务，无需打开统计页。每轮最多选择 128 条
待补齐事件，沿用最多 4 个文件、每个文件尾部 1 MiB 的读取上限；通常每 10 秒运行一轮。
缺失记录按 5 秒至 5 分钟退避，重试进度保存在 SQLite，重启后继续。成功回执停止重扫，
原始事件保持不变。超出读取窗口、路径不可用或客户端未提供记录时，结果继续为未知。
状态接口的 `evidence_worker` 显示上轮尝试、补齐和仍待补齐数量；待补齐不代表执行失败。

工作台在 SSE 首次连接、重连或收到队列溢出 `reset` 事件时重新读取持久化历史，并
合并同步期间到达的新事件；安静连接每 30 秒再核对一次。事件按 ID 去重，会话切换后
丢弃旧请求。这只恢复已成功入库的事件，无法恢复从未送达服务的 Hook。

## 分析与确认记忆

### 执行结果与验证

统计区分成功、失败、取消、仅捕获开始和结果未知，并显示已知结果与耗时样本的分母。
结构化 Hook 的整数 `exit_code` 和有限非负 `duration_ms` 可作为证据；字符串输出中的
成功字样或 JSON 片段不用于推断退出码。经同会话、同调用核对的完成记录还可补充
退出码、取消状态、耗时与开始/结束时间；仅看到 completed 不等于 exit 0。
来源冲突的结果保持未知。结果回执独立保存，随原事件级联删除；不复制工具输出。

统计和 Task 验收共用解析结果。`verification` v2 只检查最新一次匹配命令：较晚的
失败、取消、未知或未完成不能被较早成功覆盖。验证须属于 Run 目录，并在最后一次
已捕获修改之后开始；执行中发生修改或无法核对先后时，需要人工复核。该规则只覆盖
已采集修改，不证明外部文件没有变化，也不证明测试覆盖需求。
缺失或过期证据为 `needs_review`，required 项保持 blocking；没有完整评估快照不能接受。
已保存的评估保持不可变，重复读取不会重写旧结论；补充证据或升级规则须建立新 Run。

1. 用“查看证据”核对相关步骤。
2. 用“选择分析”打开 EvolveTrace 分析窗口。
3. 选择复制提示并发送给 Codex。提示包含项目、会话、规则和事件引用。
4. 核对分析结果，填写结论及适用条件，勾选确认框后保存审计记忆。

窗口准备分析输入，不自动调用模型或发送消息。Codex 原生可选弹窗和系统资源
采集尚未接入；统计不包含真实 I/O、磁盘延迟或设备可靠性指标，不能诊断磁盘损坏。

CLI 也支持显式保存已核对的结论：

```powershell
aictx audit remember demo --session-id <会话ID> --event-id <事件ID> --note "已核对的结论及适用条件" --confirm
aictx audit memory demo
```

适用条件、到期时间与替代关系可显式指定；替代只作用于同项目的旧结论，并与新结论保存为同一事务：

```powershell
aictx audit remember demo --session-id <会话ID> --event-id <事件ID> --note "已重新核对的结论" --applies-to "指定测试环境" --expires-at "2035-01-01T00:00:00+00:00" --supersedes <旧记忆ID> --confirm
aictx audit revoke demo --memory-id <记忆ID> --confirm
```

工作台分析窗口也提供这些可选字段，并可在记忆卡片撤销。已撤销、被替代或到期的结论停止回读，正文保留在最近 20 条历史中供核查；撤销同条记忆可重试。适用条件会随结论返回，仍需判断是否适合当前任务，不进行自动跨项目推广。未设到期时间的记录不会仅因时间流逝自动失效。

重复 `--event-id` 可引用最多 20 条证据，每条必须属于选定项目和会话。
结论最多 1,000 字符，保存前执行凭据模式脱敏；读取最新最多 20 条。
删除会话会一并删除依赖它的记忆。人工备注仍可能包含个人信息，导出 JSON 应按
私人数据处理。

## 后续任务回读

工作台的“项目审计记忆”区域直接展示所选项目的已确认结论、历史时间和来源会话。
加载中、读取失败与确实没有记录分别显示。这里展示的是 SQLite 审计记忆，不是 `.ai` 项目 manual 区；看到卡片也不证明记忆已被送入后续模型会话。

“最近记忆加载记录”展示服务收件时间、客户端输出时间、手工加载或 SessionStart 触发方式、上下文状态及实际返回的记忆 ID，可跳到当前记忆卡片。每 15 秒刷新，界面展示最近 5 次，服务按项目最多保留 20 次。

新版 CLI 在成功输出后，通过 loopback `POST /api/activity/memory-recalls` 上报 `audit-memory-recall/v1`。
只上报有界元数据，不包含记忆正文、源文件正文、prompt、绝对路径或原始会话 ID。
普通列表查询不会被算作加载；加载零条、部分上下文和预算截断分别保留。
记录表示 **客户端声明已返回到本地输出**，不证明宿主接收、模型采用或任务收益，也不推进 Task 的 Context Receipt 等级。
没有记录可能是未启用、未加载、旧版 CLI 或上报失败，不能当作“从未加载”。上报失败仍返回本地上下文；后台只显示已收到的记录，不扫描工作区补造历史。
已删除会话的记忆正文随会话移除，历史加载记录只保留 ID 等元数据，按上述数量上限淘汰；不在当前最新 20 条记忆中的 ID 不会被误标为已删除。

```powershell
aictx load demo --audit-url http://127.0.0.1:8001
```

只返回所选项目仍有效且未到期的 `human_reviewed` 记录，独立标记为历史观察。
回执记录实际返回的记忆 ID，不改变本地文件 freshness。附加段落最多 8 KiB，
同时受整体交付预算限制，截断会明确标记。服务不可用时，本地上下文仍会返回。

希望 Codex SessionStart 和切换项目时的 `aictx load` 都回读时，在启动 Codex 的环境中显式设置：

```powershell
$env:EVOLVETRACE_AUDIT_MEMORY_URL = "http://127.0.0.1:8001"
```

默认保持离线加载。启用后也只回读当前项目，禁用环境代理和 HTTP 重定向。
`load --audit-url` 可覆盖环境变量指定的服务地址。仅启动后端不会自动启用回读。
记忆保存于 SQLite；回读不改写 `.ai/projects/*.md` 人工块。要把结论提升为长期
项目约束，应重新核对后显式维护人工块。

## HTTP 协议

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/activity/workspaces` | 登记 `workspace-index/v1` |
| GET | `/api/activity/report` | 读取 `workspace-activity/v1`，可选 `project_id`、`limit` |
| GET | `/api/activity/status` | 读取 `activity-status/v1` 本次服务收件与登记状态 |
| POST | `/api/activity/decisions` | 保存 ignore、mute 或 unmute |
| POST | `/api/activity/memory` | 确认并保存带证据的结论 |
| POST | `/api/activity/memory-recalls` | 接收客户端成功输出后的有界加载记录 |
| GET | `/api/activity/memory/{project_id}` | 读取 `audit-memory/v1` |

全部路径仅允许 loopback 客户端。已有审计和 `ContextBundle v1` 协议保持兼容。
