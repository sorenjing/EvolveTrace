# 如何验证上下文工具确实有帮助

本文定义效果评估协议和手工记录方式，不包含已取得的效率收益。CLI 健康检查见[自测手册](self-check.md)，完整任务对照见[Context delivery evaluation](../context-evaluation.md)。

## 先分清四件事

1. 配置和 CLI 可用：版本、项目发现、标记和入口正确。
2. 上下文适合任务：必要来源在范围内，身份、版本和新鲜度可核查。
3. 可观察使用：执行记录显示相关文件被打开，或产物引用了适用来源/规则。
4. 效果改善：同等验收下，任务准备或修正负担减少，且没有更多遗漏。

包含实际加载实现的 SessionStart Hook 会读取受限的公共约定、工作区索引和匹配项目记忆，把正文返回给客户端，并记录元数据；用 `aictx usage <项目名>` 查看实际来源、字节数、摘要、新鲜度和缺口。旧版提醒型 Hook 没有这条交付链，必须同时更新插件和 CLI。`returned` 只证明本地输出，宿主接收、模型采用和收益仍未知；generated、delivered、acknowledged 等任务协议状态也不能单独证明理解。current 只覆盖记录的观察输入，并非全部源码与业务事实。

## 指标合同

| 指标 | 口径 | 采集方式与限制 |
| --- | --- | --- |
| 背景准备人工时间，主指标 | 开始定位任务资料，到预先指定来源/约束核查完成的活跃分钟 | 计入查找、补读、纠错和任务特定上下文维护；模型等待与完整历时另列 |
| 必要约束遗漏率，保障 | 未满足的必要约束数 / 预先冻结的适用约束数 | 人工按产物核对；来源被读取不代表约束被执行 |
| 来源覆盖，诊断 | 实际检查的必要权威来源数 / 预先冻结的必要来源数 | 区分 bundle 包含、执行打开、产物有依据；它们不是同一个分子 |
| 任务验收，保障 | 所有必要验收通过的任务数 / 所有纳入任务数 | 保留超时与失败，另列首次与重试成功；没有完成不能因时间短算收益 |
| 新鲜度异常，诊断 | 每任务 stale/unknown、版本不符、冲突和需要补读的数量 | 记录观察范围；缺元数据不能按“新鲜”处理 |
| 成本 | 准备/维护时间、实际交付字符或字节、可观测模型 usage | 字节数不是 Token；只算束文件不能代表整个会话输入 |

零分母记 N/A；无法测到的 usage 记 null。重复说明背景次数可辅助诊断，但要预定义“重复”，避免把正常澄清需求计为失败。

## 执行步骤

1. 挑选确实需要上下文的任务；冻结任务、commit/脏树补丁摘要、权威来源、约束、验收和预算。
2. A 使用普通仓库检索；B 使用上下文后补读源码。保持模型、权限、输入、验收和时间预算一致。
3. 在独立干净环境中执行，采用匹配任务、独立执行者或交叉顺序。先完成 A 再让同一人重复 B，会有学习偏差。
4. 运行只读检查，不为评分临时把所有来源加入 allowlist：

       aictx --version
       aictx status --workspace <workspace-root>
       aictx check --workspace <workspace-root>

5. 按[现有协议](../context-evaluation.md)准备所需交付；提前冻结来源选择。补读、失败和人工修正均记录，不把目录列表当完整源码检索。
6. 用相同验收检查产物，再比较逐项结果、人工时间与维护成本。没有合格产物时先讨论失败，不宣称节省。
7. 保存原输出和审阅；修改来源策略后用新任务验证，保留旧失败案例。

## 最小记录

| 字段 | 待填写 |
| --- | --- |
| 实验 / 任务 / 组别 / 执行顺序 | 未测 |
| 代码、数据、模型/工具与上下文版本 | 未测 |
| 必要来源及约束数 | 未测 |
| bundle 覆盖 / 实际读取 / 产物依据 | 未测 |
| 任务验收、遗漏、错误、失败原因 | 未测 |
| 人工准备 / 修正 / 维护时间 | 未测 |
| 模型等待、完整历时、usage 可用性 | 未测 |
| 配置与交付一次性成本 | 未测 |
| 原始证据位置、人工判断和局限 | 未测 |

私人任务记录保留在授权的私人工作区，公开示例只用合成资料。一次来源检查只能支持来源诊断；没有可靠对照时不能写“节省 X%”。连续没有净收益时，应简化上下文或停止该场景的维护。

方法依据：[Google HEART](https://research.google/pubs/measuring-the-user-experience-on-a-large-scale-user-centered-metrics-for-web-applications/)用于目标到指标；[Microsoft 可信实验](https://www.microsoft.com/en-us/research/articles/patterns-of-trustworthy-experimentation-pre-experiment-stage/)用于对照与数据质量。具体合同以上述任务协议为准。
